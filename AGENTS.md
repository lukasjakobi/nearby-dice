# Nearby Dice

Offline multiplayer Yatzy-style dice game over Google Nearby Connections (Expo SDK 57, React Native, strict TS).

## Read first

- Scope, product principles or open decisions → `PRODUCT.md`
- Session, protocol, navigation or saved games → `docs/technical-design.md`
- A new screen or component → `CONTRIBUTING.md`, Project structure and Conventions (the full list
  behind "Every edit")
- Native bridge, permissions or radio → `docs/technical-design.md`, Permissions
- Build, signing or CI → `README.md`, Build it yourself; `CONTRIBUTING.md`, Releases

## Every edit

- The host is authoritative: it validates every move and broadcasts the full `SessionSnapshot`;
  guests only send commands.
- ESLint enforces module barrels and the layer direction; its error names what a module may
  import. `domain` stays pure: no packages, I/O or app text.
- State values are string `enum`s; compare against enum members.
- App text lives only in `src/i18n/locales/{de,en}.json`, read with `t('namespace.key')` from
  `useTranslation()`; pure builders take `t` as a parameter. German copy is final: reuse existing
  strings, and ask before writing new German wording. Every key goes into both files.
- Game option values come from `domain/rules.ts`; setup, validation and labels derive from them.
- Screens are thin: a view-model hook or pure `build…View` produces props, components render them.
  Each component gets its own file in `components/`, hooks go in `hooks/`, builders in `view/`
  (CONTRIBUTING, "Feature folders").
- Colours come from `useTheme()`; only dice and player colours live in `ui/theme/tokens.ts`.
- Navigate via `navigate.push/replace(Route.X)` from `@/shared`. The session phase decides the
  screen (`features/session/routing.ts`).

## Gotchas

- Other agent sessions may share this checkout. Work in your own worktree under
  `.claude/worktrees/`, and set work aside with a WIP commit rather than `git stash`.
- `android/` and `ios/` are generated by `expo prebuild` and gitignored. Change native config in
  `app.json` or `plugins/*.js`; native bridge code lives in `modules/nearby-connections/`.
- Jest only runs `**/__tests__/**/*.test.ts(x)`; a test file anywhere else is silently skipped.
- The app needs a development build on real phones (Expo Go lacks the native module).
- Session behaviour is tested with real `HostSession`/`GuestSession` over `FakeNetwork` with fake
  timers; reuse `src/test/` (fixtures, `render`, `BotPlayer`) for new tests.
- Release keystores and signing credentials stay outside the repo (see CONTRIBUTING, Releases).

## Done means

- `npm run check` passes (typecheck, lint, format check, tests). CI runs the same before building the APK.
- Native and radio changes are reported as untested: the Nearby bridge is unverified on devices.
- A change to documented behaviour updates the doc that owns it, following PRODUCT.md "Keeping the
  Documentation Understandable": one place per rule, status marked **Confirmed/Proposed/Open/Verified**.
